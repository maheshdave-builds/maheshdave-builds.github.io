Two features landed in the same sprint: an ERP that POSTs "this order is exported", and a cron that retries orders the ERP never acknowledged. Both were written as separate blocks of SQL. They drifted within a month, and the cron started overwriting a status the API had just set because it did not know about the new column.

The HTTP route is not the feature. webapi.xml binds a URL to a method on a service interface. Cron, a consumer, and an admin controller can call that method without HTTP. If the only implementation lives in a controller, the cron will grow a second copy.

OrderRepositoryInterface::get() takes an entity id, not an increment id. Integrations send increment ids. getList with a filter is the supported lookup. There is no getByIncrementId on the repository interface; a helper with that name in some codebases is a local invention.

The route parameter name has to match the PHP argument name, incrementId, not increment_id. The second argument comes from the body as {"state":"exported"}. Using anonymous as the resource would publish this to the internet. The ACL resource is declared in etc/acl.xml and granted to the integration in System > Integrations, not to a human admin role, unless a person is going to call it from the admin token.

The hardcoded increment id is the shape of the call, not the selection logic. The selection belongs in a repository of your own; the point is that the cron has no curl back into /rest and no second writer. A cron that HTTP-calls the local REST API pays for auth, area emulation, and a network hop to change a row in the same database.

A token whose role lacks MaheshDave_OrderExport::status gets 401 or 403. A bad state gets a 400 with the input exception message. Then:

SELECT increment_id, state FROM maheshdave_order_export_status WHERE increment_id = '000000123';

state is exported. Run the cron class from a command or from bin/magento cron:run after you point it at a real failed order, and the same row moves to failed with a newer updated_at. Two writers, one row, one method.
