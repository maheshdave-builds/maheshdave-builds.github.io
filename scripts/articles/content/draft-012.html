The ERP base URL was set at the website scope for the EU site and left empty at default, on purpose, so the US site could not accidentally call the EU endpoint. Admin saves from the EU website worked. The cron export called the empty URL and logged "ERP base URL is not configured" for orders that belonged to the EU website. ScopeConfigInterface::getValue($path) with no scope uses the current scope. Cron, consumers, and bin/magento have no current store, so that call returns the default-scope value, which was empty.

Read the scope you mean

app/code/MaheshDave/OrderExport/Model/ErpConfig.php

storeManager->getStore($storeId)->getWebsiteId();
        $url = trim((string) $this->scopeConfig->getValue(self::XML_PATH, ScopeInterface::SCOPE_WEBSITE, $websiteId));
        if ($url === '') {
            throw new LocalizedException(__('ERP base URL is not configured for website %1.', $websiteId));
        }

        return rtrim($url, '/');
    }
}

The third argument is the website id, not the store id, because the scope type is SCOPE_WEBSITE. Passing a store id there reads a different website's row, or none, and it does not throw. The order has a store_id. Resolve the website from that store. Do not take the website id from "the current website" inside a consumer; there isn't one.

A path that is configured at store-view scope has to be read with ScopeInterface::SCOPE_STORE and the store id. Website scope does not fall through per store view. If two store views in one website must call different endpoints, the field was created at the wrong scope and no amount of getValue flags will split it. Recreate it as store scope, or the values will keep colliding.

Where the store id comes from

The export message in this project is the order id. The consumer loads the order and then asks for config:

$order = $this->orderRepository->get((int) $orderId);
$baseUrl = $this->erpConfig->getBaseUrlForStore((int) $order->getStoreId());

That is the whole fix. Iterating $this->storeManager->getWebsites() is the other correct shape, and I use it when the job is not tied to an order: a catalog push that must run once per website. Running it once and reading default scope sends every website's products to whichever URL was saved at default, including websites you thought were isolated.

Prove the scope, not the value

bin/magento config:show maheshdave_erp/connection/base_url
bin/magento config:show --scope=websites --scope-code=eu maheshdave_erp/connection/base_url

The first command prints the default, often empty. The second prints the EU URL. After the consumer change, an EU order logs the EU host. A US order, with no website value and no default, throws the localized exception naming the website id, which is the outcome you configured. If both commands print the same URL, the value was saved at default and the website field in admin was never saved; the code is then doing what it should with the data it has.
