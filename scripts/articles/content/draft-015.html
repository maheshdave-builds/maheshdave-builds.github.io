Marketing appended utm_source to every category URL. Fastly's hit rate on those categories collapsed, because the query string was part of the cache key and each combination was a new object. Someone then added a VCL pass for any request with a query string. Hit rate came back for clean URLs and category filters, which are also a query string, started hitting origin on every request. The requirement was narrower than either change: a preview=1 flag used by merchandisers must not be cached, and every other parameter must not multiply objects.

Two different operations

Passing and stripping solve different problems. return(pass) in vcl_recv sends this request to origin and does not store the response. That is correct for preview, because the preview response must not be saved and later served to a shopper. A tracking parameter should be stored, but under a key that does not include it. That is req.url rewritten before the hash, or set req.http.Fastly-Purge is unrelated; the usual Commerce approach is to remove the parameter from the URL that Fastly hashes while leaving the original available to origin if origin needs it. For UTM, origin does not need it to render a category. Remove it from the URL used as the key.

This is a custom snippet in the Fastly configuration for the Commerce service, type recv, priority after the stock Magento snippets so you do not fight their admin and checkout passes. Upload VCL after saving. A snippet that exists only in the Magento admin and was never uploaded is not running.

if (req.url.qs ~ "(^|&)preview=") {
    set req.http.X-Magento-Preview = "1";
    return (pass);
}

if (req.url ~ "\?") {
    set req.url = querystring.filter(req.url, "utm_source");
    set req.url = querystring.filter(req.url, "utm_medium");
    set req.url = querystring.filter(req.url, "utm_campaign");
    set req.url = querystring.filter(req.url, "utm_content");
    set req.url = querystring.filter(req.url, "utm_term");
}

querystring.filter is a Fastly VCL function, not part of the Varnish this site runs locally. A snippet that works in a local Varnish 6 file will fail validation on Fastly if it calls that function the other way around, and a failed validation does not activate, so the previous version stays live. That is the safe failure. Validate before activate. The manual Fastly CLI article in this set is the procedure I use when a snippet has to come back out.

return(pass) stops processing of vcl_recv. The filter block must stay below the preview check or preview URLs get stripped and then cached. Do not match req.url.qs ~ ".". That is the "any query string" pass that broke layered navigation.

What a hit looks like after this

Request the category with and without utm_source=newsletter. Both should return the same X-Cache HIT and the same Age growing together. If the ages differ, the parameter is still in the key: the snippet is not on the active VCL version. Request ?preview=1 twice. Both should be PASS or MISS, never a HIT that grows Age. If preview hits, the condition did not run, often because the parameter was added as ?x=1&preview without a value and the regex expected preview=. The pattern above requires the equals sign. Merchandisers were copying a link without it, so I also match (^|&)preview($|&) when the flag is boolean. I keep that second condition in the same if, not in a later snippet, so there is one place that decides to pass.
