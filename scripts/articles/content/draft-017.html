Category TTFB went from tens of milliseconds at Fastly to a full origin render, on every request, after a "small" header change that printed the logged-in customer's first name. The template was fine. The layout node had cacheable="false". Magento's rule is not "this block is private". It is "if any block in the layout is not cacheable, the page is not cacheable". Fastly then has nothing worth storing, because origin sends the response as uncacheable.

Find it before rewriting the page. From the Magento root, the layouts you own are the ones to change; core uses the flag for checkout and customer account on purpose.

rg -n 'cacheable="false"' app/code app/design --glob '*.xml'

The header block in this case existed only to greet the customer. Everyone else, including guests, paid for an uncached page so that one string could be personal. Customer-specific fragments in Magento are loaded in the browser from /customer/section/load after the cached HTML is served. The page stays public. The section payload is per session.

The template above is the shape, and the component name has to be a UI component that reads the section. The stock customer component reads the customer section, not yours. Use a small component that returns the section:

app/code/MaheshDave/Greeting/view/frontend/web/js/greeting.js

define(['uiComponent', 'Magento_Customer/js/customer-data'], function (Component, customerData) {
    'use strict';

    return Component.extend({
        initialize: function () {
            this._super();
            this.greeting = customerData.get('maheshdave-greeting');
            return this;
        }
    });
});

Point the Magento_Ui/js/core/app component at MaheshDave_Greeting/js/greeting. Remove cacheable="false" from the block. The phtml no longer prints the name in PHP, so the cached HTML is the same for every visitor and the name appears after customer-data loads.

Confirm the page is cacheable again

Fetch a category URL twice and read X-Magento-Cache-Debug in developer mode, or Fastly X-Cache. The second response is a HIT. View source on that HIT and confirm the first name is not in the HTML. It should appear only after the section request to /customer/section/load?sections=maheshdave-greeting. If the name is in the HTML of a HIT, the old block is still rendering it and you have two sources. If the page is still a pass, another cacheable="false" remains in the handle. The rg result is the list, not a suggestion.
