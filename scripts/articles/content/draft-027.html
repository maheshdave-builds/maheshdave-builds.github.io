The checkout step required a purchase-order number. The Knockout validation rule blocked the button. Finance then found orders with an empty number. Those orders had been placed by the customer's procurement tool, which calls PaymentInformationManagementInterface::savePaymentInformationAndPlaceOrder and never loads checkout/onepage. A UI rule is a convenience. The rule that matters reads the quote on the server.

Store the value as a quote extension attribute or a column on quote that sales converts to the order. I use a column maheshdave_po_number on quote and sales_order, declared in db_schema.xml, copied in a sales_model_service_quote_submit_before observer by $order->setData('maheshdave_po_number', $quote->getData('maheshdave_po_number')). Fieldset sales_convert_quote can do that copy too, when the field is in fieldset.xml. I use the observer when I want the copy to be obvious in code review.

The payment plugin does not trust the request parameter. By the time place order runs, the number has to already be on the quote, written by a small repository method the checkout step and the procurement API both call. Validating $this->request->getParam('po_number') passes the browser, which posts the field, and still passes an API client that never sends it, because the param is simply absent and a careless if ($poNumber) was skipped. The quote is the document both clients share.

Save the number before payment, not in the same request as place order, unless that request's service sets it on the quote object and this plugin reads the object. A plugin that runs before the code which copies the param onto the quote will reject a valid browser checkout. I set the attribute in savePaymentInformation's before-plugin only when the payment additional data contains po_number, and the require-plugin reads whatever is on the quote after that. Order them with sortOrder. The writer is 10, the requirement is 20.

With an empty maheshdave_po_number on that quote, the response is an input exception and sales_order has no new row. Set the column on the quote, repeat, and the order's column matches. The Knockout rule can stay. It is not the test. The curl is the test. Admin reorder and negotiable-quote acceptance do not call this method. If those paths must require the same number, put the same check on the service they call and keep the exception text identical.
