After a deploy, three people ran three different checks. One reindexed. One flushed cache. One looked at cron. The reindex and the flush were not checks, and they hid the actual failure. The command I want on a deploy pipeline is read-only, exits non-zero when something is wrong, and prints JSON so the pipeline can store it. It lives in MaheshDave_DevTools because it is operational tooling, not a feature of the catalog.

app/code/MaheshDave/DevTools/Console/Command/HealthCommand.php

setName('devtools:health');
        $this->setDescription('Read-only indexer, cache, and cron status as JSON');
    }

    protected function execute(InputInterface $input, OutputInterface $output): int
    {
        $indexers = [];
        $indexerBad = false;
        foreach ($this->indexerCollectionFactory->create() as $indexer) {
            $backlog = $indexer->getState()->getStatus();
            $indexers[] = [
                'id' => $indexer->getId(),
                'status' => $backlog,
                'scheduled' => $indexer->isScheduled(),
            ];
            if ($backlog !== 'valid') {
                $indexerBad = true;
            }
        }

        $invalidCaches = [];
        foreach ($this->cacheTypeList->getInvalidated() as $type) {
            $invalidCaches[] = $type->getId();
        }

        $errors = [];
        $schedules = $this->scheduleCollectionFactory->create();
        $schedules->addFieldToFilter('status', 'error');
        $schedules->setOrder('scheduled_at', 'DESC');
        $schedules->setPageSize(5);
        foreach ($schedules as $schedule) {
            $errors[] = [
                'job' => $schedule->getJobCode(),
                'at' => $schedule->getScheduledAt(),
                'message' => mb_substr((string) $schedule->getMessages(), 0, 240),
            ];
        }

        $report = [
            'indexers' => $indexers,
            'invalid_caches' => $invalidCaches,
            'recent_cron_errors' => $errors,
        ];
        $output->writeln((string) json_encode($report, JSON_PRETTY_PRINT));

        return ($indexerBad || $invalidCaches !== [] || $errors !== []) ? Command::FAILURE : Command::SUCCESS;
    }
}

Register it on Magento\Framework\Console\CommandListInterface in etc/di.xml with an item of type object pointing at this class. The command does not call cache:flush, does not reindex, and does not change indexer mode. getInvalidated() and the indexer state are reads. Cron errors are reads of cron_schedule. Exit code 1 is a failed check, not an exception. A pipeline that treats any non-zero as "deploy failed" should decide whether a single old cron error from yesterday is enough to fail the deploy. I fail on it and I delete or age out rows so yesterday's error does not block today's release. If you only want errors since the deploy started, filter scheduled_at with a from option. I did not add the option until a team asked, because a command with five flags becomes the page of commands this replaced.

Indexer status working during the deploy window fails the check even when the indexer is healthy and simply running. Run the command after setup:upgrade has finished and cron has had a cycle, not in the middle of it. scheduled: false on a catalog indexer in production is the finding I care about more than invalid, because an indexer left on save after a debug session will lock product saves. The JSON includes the flag. The exit code does not fail on it yet; I print it so a human sees it. Failing the deploy because one custom indexer is on save has cried wolf on every project where that indexer has no mview.

Run it

bin/magento devtools:health
echo $?

The output is a JSON object with indexers, invalid_caches, and recent_cron_errors. Exit 0 means every indexer reported valid, no cache type was invalidated, and cron_schedule had no error rows in the five most recent errors, meaning none. Exit 1 is a reason to look at the JSON, not a reason to flush. If the command itself is missing, setup:di:compile has not picked up the CommandListInterface argument, or the module is disabled.
